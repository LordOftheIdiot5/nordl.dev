Case study

navprofit

Does this voyage actually make money?

Voyage economics are usually settled after the fact. Freight is agreed, fuel is burned, port and agency costs land weeks later, and the margin is a number someone works out once the voyage is already over. navprofit puts that number on screen while the ship is still moving.

What it does

  • Live vessel positions. AIS streaming, so the fleet on the map is where it actually is rather than where the last report said.
  • Bunker prices by port. VLSFO indications per port, joined to the voyage so fuel cost is a live figure rather than an estimate.
  • Per-voyage P&L. Revenue against fuel, port and agency costs, with the margin and the cost-to-revenue split visible per leg.
  • Invoices and alerts. What is outstanding, what is paid, and thresholds that fire when a margin drops or a price moves.

How it is built

A browser application with no server holding your data. API keys for AIS and bunker pricing stay in the browser and talk to those services directly, so there is no shared key, no shared quota, and nothing of yours sitting on someone else's machine. Currency and home port are settings rather than assumptions — it defaults to NOK and Bergen because that is where it was written.
